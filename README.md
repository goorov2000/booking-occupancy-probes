# booking-occupancy-probes

Снимок загрузки объектов размещения (глэмпинги, хаусботы) по их **публичным модулям
онлайн-бронирования** — без API владельца, без браузера, без агента в цикле.
Модуль вырос внутри более крупного проекта Content Factory как скилл агента
`/glamping-occupancy` и вынесен сюда как самостоятельный проект: код, тесты на
фикстурах, документы постановки и инструкция агенту (`SKILL.md`).

## Задача

Исследование: понять реальную загрузку десятков загородных объектов, у которых нет
API, — по тому, что их собственный виджет бронирования показывает любому посетителю
(свободно / занято / цена / остаток домиков). Один агентный прогон браузером снимал
5 объектов из 19 за полтора часа и не повторялся дёшево; нужен был инструмент
«запустил командой — через минуты свежий снимок», с историей для динамики.
Для объектов без модуля вообще (хаусботы) — телефонный канал: лист прозвона →
ответы человека → снапшот в том же формате.

## Архитектура

| Звено | Файлы | Что делает |
|---|---|---|
| Пробники | `occupancy/probes/*.py`, диспетчер `probes/__init__.py` | детерминированный съём: рецепт → HTTP-запросы к виджету → сетка «юнит × ночь» |
| Разведчик | `occupancy/scout.py`, `scout_apply.py` | по HTML сайта опознаёт движок (список, не первый маркер), добывает параметры, собирает справочник юнитов; черновик рецепта с исходом `high` / `low` / `refuse`; перенос в реестр только после проверки пробником |
| Ядро и реестр | `occupancy/occupancy_core.py` | SCHEMA рецепта/снапшота/целей, метрики в домико-ночах, дифф, атомарная запись, блокировки |
| Снапшоты и леджер | `cli.py`, `ledger.py` | датированный каталог на прогон (файл на объект, `run.json` пишется в начале), производный слой сезонности: замороженный факт прошедших ночей и кривая темпа |
| Сводки и страницы | `build_summary.py`, `build_units_report.py`, `build_units_page.py` | markdown/html сводка, поюнитный отчёт (xlsx + md), страница по постоянной ссылке |
| Плановый прогон | `run_scheduled.py`, `deploy/systemd-user/` | user-таймер 06:30: один вызов CLI на все цели, дедлайн и бюджет на цель, параллелизм по хостам, песочница vs бой, копия данных, ротация; сбой одной цели — строка `insufficient_data`, а не падение |
| Телефонный канал | `phone_channel.py` | `sheet` — лист прозвона на неделю (три окна ночей, сценарий вопроса); `ingest` — заполненный лист → объекты снапшота с `engine: "phone"` |
| Дайджест | `tg_digest.py` | короткий текст по цели после прогона; транспорт — внешний |
| Агент как шаг cron | `publish_pages.sh` | headless-сессия агента с одной задачей: переопубликовать две страницы по их постоянным url |

## Движки и способ съёма

| `engine` | Как снимается |
|---|---|
| `travelline` | TL Integration: три GET (`hotel_info`, `room_type_availability_2`, `hotel_booking_rules`) окнами по 90 суток; фонд — POST `hotel_availability` на ночь |
| `bnovo` (= reservationsteps) | GET `min_prices` по категории; `null` = не продаётся; фонд — `/v1/api/rooms` или `data-available` со страницы подбора; ветки `grid_source: rooms` и `min_stay` |
| `bronirui` («Бронируй Онлайн») | POST `widget/calendar` на каждый `number_id` (snake_case, Origin/Referer обязательны); справочник — союз `numbers` на 2–3 пары дат |
| `litepms` | календарь приходит готовым HTML; два макета (вертикальный и сеточный), дата берётся только из `title`/`month-title` |
| `homereserve` (RealtyCalendar v2) | POST `apartments` + `calendar`; единица продажи — конкретный домик |
| `rc-bookings` (старый виджет RealtyCalendar) | GET `search` окнами в 1 и 2 ночи: домик, пропавший из выдачи, занят; `price.json` про занятость не знает |
| `uhotels` (artDg) | POST `rooms` на ночь окнами 1–2 ночи; `max` категории — остаток домиков |
| `bookonline24` (Контур.Отель) | `entities` + POST `availabilities/daily` (ночь есть в ответе = продаётся) + `accommodation-prices/all` для остатка |
| `frontdesk24` | POST `getHotelParams` (признак живого токена), `getAvailableDates` окнами, `getVariants` для фонда |
| `sutochno` | агрегатор: GET `getOrdersByObject` — будущие блоки календаря объявления; всегда `source_kind: aggregator_quota` |

Общие правила пробников: один запрос — одна попытка, пауза ≥ 1,2 с на хост
(с джиттером), Retry-After уважается, ничего не бронируется, формы не отправляются,
капчи и антибот не обходятся. 4xx/смена схемы → рецепт `broken` с причиной;
5xx и сетевой сбой → `unknown`, рецепт жив; 403/429 → отдельный исход `refused`,
рецепт ломается только после трёх суток отказов подряд.

## Форматы (SCHEMA в `occupancy/occupancy_core.py`)

- **Рецепт** (`recipes.json`, ключ — username): `site`, `engine`, `status`
  (`ok`/`broken`/`no_module`/`aggregator`), `request` (`url_template`, `method`,
  `params`, `headers`, `date_substitution`), `discovered_at`, `notes`, `source_urls`,
  у `broken` — `broken_reason`; счётчик `refusals`.
- **Снапшот** — каталог `snapshots/<YYYY-MM-DD-HHMM>/`: `run.json` (план, `started_at`,
  `finished_at`, `objects_written`) и `<username>.json`: `units` → `{юнит: {дата:
  {"state": free|busy|sales_not_open|unknown, "price", "units_total", "units_free"}}}`,
  `status` (`ok`/`partial`/`insufficient_data`) с `reason`, `source_kind`
  (`module`/`aggregator_quota`/`none`), `inventory_until`, `grid_until`, `probe_version`,
  `recipe_hash`. Агрегаты не хранятся — считаются заново.
- **Цели** (`targets.json`): порядок строк = важность; флаги `reference`, `notify`,
  `title`, `region`.

## Запуск локально (без сети)

```bash
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt   # Windows: .venv\Scripts\pip
python -m pytest -q                       # 1137 тестов, все на фикстурах, сеть заблокирована в conftest
python occupancy/cli.py --fixture grid.json --snapshot-root ./snapshots --recipes ./recipes.json
```

`grid.json` — объект снапшота по SCHEMA (б) без `checked_at`/`status`/`reason` (они
дозаполняются). Живой съём: `cli.py --probe <username> --recipes <recipes.json>`;
разведка сайта: `scout.py --url <сайт> --key <ключ>`. На Windows задайте
`PYTHONUTF8=1`. Внешний ключ приложения Суточно.ру в репозитории заменён
плейсхолдером: боевое значение — `SUTOCHNO_APP_TOKEN` или `params.token` рецепта;
при отказе `need_update_token` пробник сам достаёт свежий ключ из публичного бандла.

## Ограничения и честность оценок

Все проценты — **оценка сверху**: «занято» и «закрыто владельцем» в виджете
неотличимы. Там, где движок торгует типом, а не домиком, и фонд не снят, цифра
занижена и помечается «по типам». `sales_not_open` и `unknown` в знаменатель не
входят. Квота агрегатора никогда не смешивается с модульными цифрами без пометки.
Правило «стены» отличает закрытое окно продаж от аншлага; у Суточно длинный блок
не-`cs-book` читается как закрытые продажи. Сводка сама пишет эти оговорки.

## Что не включено

Реестры целей, рецепты, снапшоты, леджер и отчёты по реальным объектам
(`agent-runtime/…`), документы исследования и контакты (`docs/research/…`), отчёт
пилота и тикет 07, пакет `cf` (Run Log, транспорт телеграма) — данные и контур
конкретного исследования; их форматы описаны в SCHEMA. Имя заказчика в текстах
заменено на роль, ключ приложения одного из движков вынесен в переменную окружения,
названия объектов рядом с оценками загрузки в документах и комментариях убраны.
Фикстуры тестов — реальные ответы публичных виджетов бронирования и открытых
страниц на даты снятия (август–сентябрь 2026): названия объектов публичные,
персональных данных в них нет, а сами данные любой посетитель сайта видит в виджете.
Импорт `cf` в `run_scheduled.py` уже был best-effort (`try/except`),
поэтому без пакета уведомления и Run Log просто пропускаются; для тестов лежит
заглушка `tests/_stubs/cf/`.
