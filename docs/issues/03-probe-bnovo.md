# 03 — Пробник Bnovo: рецепт → живая сетка доступности

**What to build:** детерминированный съём загрузки объекта на движке Bnovo
(2 из 19: a_ureki, chekhovapi — оба со статусом ok в `calendars-out/`).
Вход — рецепт из реестра, выход — сетка доступности в модели тикета 01,
поюнитно по категориям с ценами. Bnovo-виджет показывает карточки категорий
с «Здесь нет свободных мест…» на конкретные даты — пробник снимает то же
самое из JSON-запросов виджета, без браузера.

Живые фикстуры и параметры рецепта — снять браузером с a_ureki
(эталон — ручной осмотр 11.08; числа по конкретным объектам в витрине опущены). Ничего не
бронировать, капчи не обходить.

## Комментарии

Главная находка разведки (чистый HTTP, браузер не понадобился): «модуль
Bnovo» и «вариант reservationsteps» движка travelline (тикет 02) — ОДНА
платформа. Сайт Bnovo-объекта грузит
`widget.reservationsteps.ru/iframe/library/dist/booking_iframe.js`
(конструктор `BookingIframe({uid})`), iframe открывает
`reservationsteps.ru/rooms/index/{uid}`, страница брендирована Bnovo
(bnovo.js, ссылки bnovo.ru), данные — с
`public-api.reservationsteps.ru/v1/api/min_prices`, ровно того эндпоинта,
что у «travelline»-объектов yck_kuzminskoe и ok_reka. То есть
reservationsteps.ru — движок Bnovo, а волна 2 у той пары объектов платформу
не различила. Поэтому кода съёма в тикете НЕТ: `probes/bnovo.py` — тонкий
алиас (`probe = travelline.probe`), engine=bnovo зарегистрирован в
диспетчере, существующие рецепты не переименовывались (ключ реестра —
username, engine лишь выбирает пробник, оба имени ведут в один код).

Реализация: `probes/bnovo.py` (алиас + инструкция разведчику в докстринге),
регистрация в `probes/__init__.py`, тесты `tests/test_probe_bnovo.py` на
живых обезличенных фикстурах `tests/fixtures/bnovo/` (тела — только даты и
цены; каталог отдельный от travelline, потому что фикстуры сняты с
Bnovo-объектов, хотя парсер общий). Существующий тест «неподдержанный
движок» переведён с bnovo на litepms. Всего по скиллу 60 зелёных.

Разведанные параметры рецептов (оба status=ok, поюнитные категории в
params.room_types):

- **a_ureki** (aureki.ru): uid `3bfd46cf-…` из BookingIframe на /booking,
  11 жилых категорий («Подарочный сертификат» 281471 не включён — не жильё;
  у этнодомов несколько физических юнитов: null категории = проданы ВСЕ,
  оценка сверху). Справочник снят с `rooms/index/{uid}?dfrom=…&dto=…` на
  свободные даты — сервер рендерит только доступные категории, поэтому
  проверен союз трёх дат (22-23.09, 20-21.10, 08-09.12) — списки сошлись.
- **chekhovapi** (chekhovapi.com): uid `53b6c90b-…`, 14 категорий из
  фильтра карточек (data-category-id/data-name); глэмпинг-юниты — 621467
  «Глемпинг в лесу» и 140679 «Глемпинг с красивым видом на закат»,
  остальное — номера/виллы/дача/квадродомы той же базы (эталон волны 2 —
  агрегат по всему объекту, поэтому в рецепте все категории; сводке по
  глэмпингам смотреть на эти два юнита).

Глубина горизонта (вопрос тикета): API отдаёт ЛЮБОЙ запрошенный диапазон
дат — глубже «текущий+следующий месяц», который виджет показывал волне 2
в браузере. Живые тарифы на 14.08: a_ureki до 29.12.2026, chekhovapi до
29.11.2026. За границей окна продаж ВСЕ ночи null — неотличимо от занято
(в снапшоте станут busy-оценкой сверху), поэтому горизонт сводки держится
в окне продаж; дефолт «сегодня → конец октября» внутри окна обоих объектов.

Живая сверка (прогон 14.08; эталоны волны 2 — агрегатные «день занят, когда
нет ни одной свободной категории», поэтому сверка шла по агрегату из
поюнитной сетки на общем окне 14–31.08): у обоих объектов месяцы сошлись с
эталоном дата-в-дату либо разошлись на объяснимый дрейф броней за три дня
(новые пары пт–сб, одна отмена подряд идущих ночей). Поюнитная занятость
закономерно выше агрегатной — тот же эффект, что в тикете 02. Числа по конкретным объектам в витрине опущены.

Для переразведки (тикет 05): способ добычи uid и room_type_id — в
докстринге `probes/bnovo.py`; account_id (нужен только эндпоинту
`/v1/api/rooms`, не рецепту) у a_ureki — 11896 из hidden input листа
ожидания на rooms/index, у chekhovapi такой формы нет — и не нужна,
рецепт живёт одним uid.
