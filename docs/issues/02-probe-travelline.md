# 02 — Пробник TravelLine: рецепт → живая сетка доступности

**What to build:** детерминированный съём загрузки объекта на движке
TravelLine (самый частый: 8 из 19 модульных объектов прошлого прогона,
включая варианты ibe.travelline.ru и ibe.tlintegration.ru). Вход — рецепт из
реестра (шаблон запроса виджета с подстановкой дат), выход — сетка
доступности в модели тикета 01, поюнитно по категориям, с ценами где
отдаются. Агрегированный календарь TravelLine красит дату занятой только
когда проданы ВСЕ типы юнитов — пробник обязан работать на уровне категорий,
а не агрегата; если удалось снять только агрегат, сетка помечается как оценка
снизу и это видно в снапшоте.

Для получения живого слепка трафика (фикстуры) и параметров рецепта — снять
их браузером с 1–2 реальных объектов, у которых движок известен по
`calendars-out/` (объект-эталон прошлого прогона). Ничего не
бронировать, формы не сабмитить, капчи не обходить; запросы щадящие.

## Комментарии

Реализация: `occupancy/probes/` —
`__init__.py` (диспетчер по engine + `run_recipe`/`mark_recipe_broken`),
`travelline.py` (оба варианта движка); probe-режим CLI
(`cli.py --probe <username> [--recipes PATH] [--date-from/--date-to]`);
тесты `tests/test_probe_travelline.py` + probe-режим в `tests/test_cli.py`
(52 зелёных на весь скилл); живые обезличенные фикстуры —
`tests/fixtures/travelline/` (без cookies/токенов: тела ответов — только
даты/цены/коды категорий).

Движок оказался ДВУМЯ разными API (оба встречались волне 2 как travelline):

- **reservationsteps.ru** (yck_kuzminskoe, ok_reka):
  `GET public-api.reservationsteps.ru/v1/api/min_prices?uid=…&dfrom=DD-MM-YYYY
  &dto=…&room_type_id=…` на каждую категорию из рецепта; null = ночь не
  продаётся (занята/закрыта — неотличимо, оценка сверху), пустой
  `{"min_prices":[]}` = тарифов нет вообще → sales_not_open (живой случай
  ok_reka: модуль подключён формально, продаж нет до 2027 — рецепт записан
  status=ok с оговоркой в notes, снапшот честно даёт «продажи не открыты»,
  а не 100% занятости). Без room_types в params пробник снимает агрегат
  (granularity=aggregate — видно в снапшоте). Глубина продаж yck проверена
  до марта 2027 — движок отдаёт глубже конца октября.
- **TL Integration** (istracottage 11269, novo_okatovo 16708): три лёгких GET
  на объект — `BookingForm/hotel_info` (справочник категорий + окно продаж
  `availability_max_date`), `AvailabilityCalendar/room_type_availability_2
  ?aggregate_dates=false&max_nights=1` (поночный календарь КАЖДОЙ категории с
  ценами на весь горизонт одним запросом; проданные ночи в ответе просто
  отсутствуют), `AvailabilityCalendar/hotel_booking_rules` (агрегат — только
  для толкования ночей, пустых у всех категорий: forbidden → busy, за окном
  продаж → sales_not_open, иначе unknown). Эндпоинт календаря снят браузером
  из живого трафика дейтпикера и сверен 1:1 с тяжёлым
  `BookingForm/hotel_availability`. WAF Qrator пропускает чистый HTTP с
  браузерными Referer/Origin — 403 волны 2 были на корень домена и угаданные
  пути, не на реальные API. `hotel_code` резолвится без браузера:
  `GET /integration/profile/{TL-INT-context}/ru` → `booking-form.provider`
  (context лежит в HTML сайта) — готовый путь для разведчика (тикет 05).

Сверка с эталоном (прогон 14.08): поюнитная занятость сошлась с ручным
осмотром 11.08 в пределах дрейфа броней за три дня (расхождения объяснены
конкретными датами). Побочное подтверждение тезиса тикета: поюнитный съём
TL-объектов даёт заметно больше агрегатного календаря волны 2, который
красит день занятым только при продаже всех категорий. Числа по конкретным объектам в витрине опущены.

Нюанс чекбокса про ошибки (осознанное решение): рецепт помечается broken
(поле `broken_reason`, добавлено в SCHEMA (а) — см. комментарий тикета 01)
при СМЕНЕ СХЕМЫ ответа, 4xx и не-JSON теле (антибот/капча) — это сигнал
переразведки. Чисто СЕТЕВОЙ сбой (таймаут, обрыв, 5xx) рецепт не ломает:
объект получает insufficient_data/partial с причиной, потому что переразведка
транзиентного сбоя не чинит — нужен повтор прогона. Ретраев нет нигде, паузы
между запросами ≥1.2 с, таймаут 25 с.

astroglamp и zapovednik_glamp: их hotel_code ещё не резолвлен из context
