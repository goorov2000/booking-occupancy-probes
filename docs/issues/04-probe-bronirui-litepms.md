## Комментарии

Реализация: `probes/bronirui.py` и `probes/litepms.py`, регистрация в
`probes/__init__.py` (все четыре движка v1 в диспетчере); тесты

обезличенных фикстурах `tests/fixtures/bronirui/` и `tests/fixtures/litepms/`

замаскирован, sid и фото из litepms-HTML вырезаны). Тест «неподдержанный
движок» переведён с litepms на aggregator-ostrovok (тикет 05). Схема тикета
01 не менялась: новые ключи (`numbers`, `module_id`, `property_id`) живут
внутри свободного `params` рецепта, `broken_reason` уже был в SCHEMA (а).

**«Бронируй Онлайн» (bronirui-online), чистый HTTP — браузер не понадобился.**
Виджет znms ходит POST-ами с JSON в `api.bronirui-online.ru/v2`. Два ключа,
о которые споткнулась волна 2 (`401 Лицензия не подключена`): поля тела —
snake_case (`module_id`), а не camelCase `moduleId`; и календарь
`widget/calendar` без `number_id` конкретного номера отдаёт ВСЕ ночи
isClosed — поюнитный `number_id` обязателен (агрегатного съёма у движка
нет; рецепт без `params.numbers` — честный insufficient_data). Ответ:
`dates.elements{YYYY-MM-DD: {isClosed, price}}`; isClosed=true = занята или
закрыта владельцем (неотличимо, оценка сверху), false = свободна с ценой.
Справочник номеров — союз POST `/v2/numbers` на 2–3 пары дат в разных
месяцах (метод тикета 03). Origin/Referer сайта обязательны (домен
проверяется по списку доверенных).

**litepms — JSON API наружу нет, календарь отдаётся готовым HTML** одним
GET `litepms.ru/widget/calendar?id={property_id}&mode=embed&d=01-MM-YYYY`
без авторизации: room-item на юнит, month-table на 3 месяца от якоря d,
клетки freeday/booking (модификаторы start_booking/end_booking/holiday/
today/lastday поверх). Даты собираются из month-title + day-number (data-id
несёт unix-время в поясе объекта — для не-МСК ненадёжно). Цен в календаре
нет. Пробник шагает якорями по 3 месяца до покрытия горизонта.

**Глубина горизонта (вопрос тикета).** bronirui: запрошенный диапазон
отдаётся целиком, живые цены vlesu — вплоть до июня 2027 (стены «всё
закрыто» не видно). litepms: якорь d листает сколь угодно далеко (проверено
до июня 2027), но за открытым владельцем окном продаж ВСЕ дни всех юнитов
рисуются booking — «закрыто» и «занято» поклеточно неотличимы. Отсюда
правило пробника litepms: полный календарный месяц, где заняты все дни всех
юнитов, читается как sales_not_open (ложные 100% в сводке хуже недоучёта
редкого полностью проданного месяца; sales_not_open из знаменателя
исключается). Текущий месяц правилом не задевается: прошедшие дни виджет
рисует freeday. У bronirui sales_not_open не ставится: стены нет, а полный
закрытый месяц ОДНОГО юнита (у ивы три юнита закрыты весь октябрь — похоже
на сезонное) от распроданного неотличим и честно читается busy-оценкой
сверху — та же семантика, что у bnovo за окном продаж (тикет 03).
